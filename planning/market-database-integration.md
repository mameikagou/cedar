# K 线产品数据库接入

用户要求：数据湖作为上游，先导入数据库，再以面向前后端的格式提供行情。业务 HTTP 请求不直接读取数据湖。

## 删除旧批次

2026-10-08 已核对目标数据库为 `cedar`、角色为 `cedar_app`，仅有招商南油 667 条日线，范围 2024-01-02 至 2026-10-08，对应旧同步时间为 2026-10-08 14:38:43.263205 UTC。

在锁表事务中重新验证股票、总条数、日期范围、同步时间及最后一条数据后，删除该股票该日期范围内的 667 条记录和精确匹配的 1 条同步记录，确认剩余行情为零。未删除表、数据湖文件或 analyze2quant 记录。仅移除了 Cedar runtime.env 中复制的 Tushare token，原项目凭据未改动。

## 最终数据链路

`analyze2quant current 版本 → 注册 Parquet → 独立导入任务 → Cedar PostgreSQL → /api/market/kline → TradingView`

- 导入入口：`python -m cedar_api.import_market`，只读上游库，目标限定为 Cedar 库。
- `market_daily`：证券代码、交易日、OHLC、昨收、涨跌幅、成交量（股）、成交额（元），主键为证券＋交易日。
- `market_sync`：来源数据集、不可变版本 UUID、内容 hash、来源发布时间、导入时间、最近版本检查时间、转换器版本。
- API：`time` 使用 ISO 日期，`preClose` / `pctChange` 使用 camelCase；缺失参考价或成交额保留 null。响应明确价格为不复权、币种人民币、量为股、额为元。
- 一个源版本解析注册对象；校验大小、SHA-256、行数和字段后，只导入该股。行情和来源记录同时事务提交。空数据、重复日期、错误股票、未知单位来源或损坏对象均拒绝导入，保留旧快照。
- Cedar 数据库 advisory lock 防止并发导入。同一来源版本和转换器版本未变时只更新检查时间，不重复写行情。
- `cedar-market-import.timer` 每 15 分钟检查。首次发布在激活前导入，部署健康检查包含产品行情接口。
- 导入器使用独立的私有 market.env，HTTP 服务的 runtime.env 不保存数据湖凭据。

## 已验证

首次从已发布湖版本导入 1,868 根日线，范围 2019-01-08 至 2026-09-18。重复运行返回 unchanged。日线本身比复权因子更新慢，不能把其他 dataset 的最新日期冒充最后交易日。

前后端检查、单位和对象校验、数据缺失行为、周期聚合、均线检查通过。另用 PostgreSQL 会话临时表验证导入 SQL 中途失败会同时回滚行情和来源记录，其他股票保持原数据；临时表在连接退出时清理。

浏览器实际验证桌面与 360/393/768px 布局、主题切换、十字光标、周期和范围切换、均线和成交量开关、图片导出，没有页面横向溢出或运行时异常。

页面标注最后交易日和入库时间；历史落后超过 7 个自然日或来源检查超过 1 小时显示提示。Cedar 不调用外部供应商补数，数据更新由 analyze2quant 原链路负责。
